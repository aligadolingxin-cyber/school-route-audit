# Design

## Context

動機見 `proposal.md` — Why。此處僅列影響技術取徑的現況與限制。

**地圖工具已提供的基礎**：`map-explorer-mvp` 已產出全國 22 縣市的人行道路段（92,273 段）與台北市的道路中心線，每一段皆有穩定識別碼；已有可運作的街景整合（`app/js/streetview.js`），含金鑰注入、無影像時的退場與視角同步。本 change 不重造這些。

**原規劃為研究等級**：本 change 的初版按研究普查設計——多輪獨立評估、重評盲化、與既有 MAPS 研究可比的分離計分、約 220 個單位。那些需求服務的是研究效度。本專案的定位見 `docs/prior-art.md`，不需要它們，故一併移除。範圍縮至 10–15 個示範單位。

**部署型態**：與地圖同為 GitHub Pages 上的靜態網站，無後端、無寫入端點。

## Goals / Non-Goals

**Goals:**

- 評估結果必然能接回地圖——以同一套識別碼為前提，而非事後對應。
- 判準可修訂而不需改程式。
- 每一句由系統產生的敘述都可追溯至具體項目與作答。
- 證明評估層可運作，並量出實際評估速率。

**Non-Goals:**

- 不做多輪獨立評估、重測信度與重評盲化。
- 不做與既有 MAPS 研究可比的分離計分。
- 不做後端、帳號或多人協作。
- 不做研究規模的普查；範圍限於示範。

## Decisions

### D1. 評估單位直接引用地圖工具的識別碼，不另建單位檔

待評清單為一份識別碼陣列，指向 `app/data/sidewalk/*.geojson` 與 `app/data/roads/*.geojson` 中既有的路段。

**理由**：原規劃要自行切段、自訂語意識別碼、維護單位檔。但地圖工具已經做完那件事，且其識別碼的穩定性已有明確設計（`map-explorer-mvp` D9：語意鍵加代表點雜湊，碰撞時才加原始幾何雜湊）。沿用它省掉整套工作，更重要的是**兩套識別碼若各自獨立，評估結果就接不回地圖**——那正是本 change 存在的目的。

**代價**：評估範圍受限於地圖工具已產出的縣市。目前道路圖層僅台北市，人行道則 22 縣市皆有。

### D2. 判準為 MAPS-Mini 加台北在地項目，存於 JSON

判準 23 項：MAPS-Mini 的 15 項（滿分 21，與原工具一致），加上騎樓、巷弄、機車佔用步行空間等在地 8 項（滿分 13）。帶版本號，每項標明來源（`maps-mini` 或 `local`）。

**格式改為 JSON 而非原定的 YAML**：瀏覽器沒有內建 YAML 解析器，而本專案不使用建置工具鏈，引入一個函式庫只為讀設定檔不划算。JSON 是原生的。

**路口題的調整**：MAPS-Mini 的 Crossing 區段原需「路口」作為獨立單位，本工具的單位是路段。直接刪除會失去行人號誌、路緣斜坡與行穿線——那正是對學童最關鍵的三項。故限定於「該路段終點的路口」，並於判準檔的 `adaptations` 明確記載此為對原工具的調整。

**低信度標記**：MAPS-Mini 第 6、7 題（建物維護、塗鴉）在街景上的信度偏低（Yu et al. 2025 於台北實測美觀類項目 kappa 明顯偏低），標記為 `low_reliability`，介面應提示。

**開放資料已有的欄位並陳但不預填**：第 9 題（有無人行道）與路緣斜坡在開放資料中已有對應欄位。介面並陳作為對照，但不自動填答——預填會錨定判讀，使評估淪為確認既有資料。

**理由**：MAPS-Global 有 123 項，15 個單位即近兩千次判讀，示範做不完。MAPS-Mini 是 Sallis 實驗室為實務工作者設計的精簡版，用於示範名正言順。而**在地那幾項才是差異化所在**——騎樓與巷弄不存在於任何開放資料集，也不在任何西方工具中。

**替代方案**：MAPS-Global 的路段區段（30 項）——較完整但示範成本高一倍；MAPS-SRTS（90 項）——學校專用但更重。

### D3. 與地圖同一個靜態網站，結果存 localStorage 並可匯出匯入

工作台為 `app/audit.html`，與地圖共用部署、街景模組與資料。評估結果存於 `localStorage`，可匯出為 JSON、亦可匯入還原。

**理由**：無後端即無需管金鑰、權限與維運，且與現有部署一致。匯出檔納入版本庫後即成為地圖的風險圖層來源，整條路徑不需要伺服器。

**這是刻意的取捨，且與原規劃相反**。初版 design 明確否決 localStorage，理由是「研究資料的存續優先」——那是對約 220 個單位的研究普查而言。現範圍為 10–15 個示範單位，且必須有匯出與匯入才成立：

- **匯出**使結果能離開瀏覽器並進入版本庫。
- **匯入**使評估能在另一台裝置或清除資料後接續。只有匯出的話，換台電腦就得重來。
- **未匯出提示**使風險看得見——清除瀏覽資料會遺失未匯出的作答，這件事必須在資料還在的時候講，不是事後。

### D4. 沿用地圖工具的街景模組

工作台直接引用 `app/js/streetview.js`，不另寫一份。

**理由**：該模組已處理金鑰注入、`gm_authFailure`、無影像時的退場與視角同步——那些是實作時真正花時間的部分，且已驗證過。兩處若各寫一份，金鑰或條款有變時要改兩個地方。

### D5. 「無法判定」不計為 0 分，而是自分母中扣除

計分時，記為「無法判定」的項目不計入該單位的分子與分母。系統呈現分數時一併標明有幾項未能判定。

**理由**：若視為 0 分，看不清楚的路段會被評得比實際差，而那些路段往往正是影像品質最差的巷弄——誤差會系統性地偏向同一個方向。

**代價**：不同單位的分數基於不同的項目數，跨單位比較需留意。故分數必須與「未能判定的項目數」一併呈現，不得單獨引用。

### D6. 匯出檔以單位識別碼為鍵，供地圖直接讀取

匯出格式為以識別碼為鍵的物件，每筆含分數、各項作答、無法判定的項目數、判準版本與評估時間。

**理由**：地圖端的 `road-segments` 已設計為可插拔的著色依據（`map-explorer-mvp` D10），只要有一份「識別碼 → 分數」的對應即可新增一個著色依據，不需改寫圖層。以識別碼為鍵可直接查表。

## Risks / Trade-offs

**未匯出的評估會因清除瀏覽資料而遺失** → 這是 D3 的已知代價。緩解：介面持續顯示未匯出的作答數、關閉頁面時提示、匯入功能使遺失後可自最後一次匯出復原。

**在地項目未經信度檢驗** → 騎樓、巷弄、機車項目為本案自訂，無既有信度數據。本 change 已移除重測信度的相關需求，故無法以數據支持其一致性。緩解：判準檔以來源標記區隔，匯出資料可將在地項目與 MAPS-Mini 項目分開檢視；任何對外陳述須一併說明此限制。

**單一評估者的主觀性** → 無第二位評估者可比對。這是範圍縮減的直接後果，非工程問題。對外陳述時須說明結果為單一評估者的判讀。

**街景影像日期與人行道資料年月不一致** → 人行道資料為 2026-06，街景影像日期不一。緩解：介面顯示影像日期，評估者可據以判斷；匯出資料記錄評估時間。

**道路圖層僅台北市** → 查無人行道紀錄的道路目前只有台北市可評。緩解：示範範圍本就設定在台北市；擴充需先跑其餘縣市的道路管線（`map-explorer-mvp` task 3b.6）。

## Migration Plan

**接入地圖的風險圖層**：匯出檔置於 `app/data/risk/`，地圖端新增一個著色依據讀取之。既有圖層不需改動。

**判準版本升級**：新版判準以新版本號發布。既有紀錄保留其原版本標記；匯入版本不符的檔案時系統明確告知，不自動重新計分。

## Open Questions

- 在地項目的具體題目與選項，需先讀內政部建研所「騎樓及人行道路無障礙改善研究」後擬定。不影響架構。
- 風險分數的計分權重。屬判準檔的設定，可於實測後調整。
