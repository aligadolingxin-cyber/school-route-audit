# Proposal

## Why

`map-explorer-mvp` 已將政府開放資料所能回答的部分做完：哪裡有人行道、多寬、哪裡出過致命事故。台北市 18,292 段有紀錄的人行道中 58.6% 淨寬未達法規下限，另有 8,422 段道路查無人行道紀錄。

但**開放資料的極限也很清楚**。騎樓被佔用、巷弄有無連續步行空間、機車停在哪、行穿線品質、路口視距——這些同樣決定學童安全的因素，沒有任何資料集收錄。地圖上那些路段的「風險分數」目前一律顯示「未提供」，並說明須由人逐段判讀。

本 change 做出那個「人逐段判讀」的工具，並把結果接回地圖成為風險圖層。那是本專案與既有工具（見 `docs/prior-art.md`）的差異所在，也是唯一無法靠取用程式碼取得的部分。

## What Changes

- 新增**評估工作台**頁面：左側街景、右側判準表，逐一評估路段。與地圖同屬一個靜態網站，共用資料與部署。
- **評估單位直接引用 `map-explorer-mvp` 已產出的路段識別碼**，不另建單位檔。兩者以同一套識別碼對應，結果必然接得回去。
- 判準以 **MAPS-Mini（15 項）為骨幹**，另加**台北在地項目**（騎樓、巷弄、機車佔用步行空間），約 23 項。
- 評估結果存於瀏覽器並可匯出 JSON；匯出檔納入版本庫後，由地圖讀取為風險圖層。
- 記錄每個單位的評估耗時，用以推估擴充至更大範圍所需工時。
- 「無法判定」為合法作答值，與「尚未作答」區分。街景看不清楚是常態，那是資料狀況不是錯誤。

## Capabilities

### New Capabilities

- `audit-units`：評估單位的來源與範圍——引用地圖工具的路段識別碼，並定義如何指定要評估的子集。
- `audit-instrument`：判準內容。MAPS-Mini 項目、台北在地增修項目、各項的作答型態、「無法判定」的處理，以及計分。
- `audit-workbench`：評估介面。街景與判準表並排、單位間導覽、進度呈現、耗時記錄。
- `audit-records`：評估結果的保存、續作與匯出，以及與地圖工具的接合格式。

### Modified Capabilities

（無）

## Impact

- **與 `map-explorer-mvp` 的關係**：本 change 消費其路段識別碼，產出其風險圖層所需的資料。地圖端已於 `road-segments` 預留可插拔的著色依據，接入時不需改寫圖層。

- **判準來源**：MAPS-Mini（Sallis 實驗室，問卷與圖解手冊開放下載，頁面未載明授權、費用或申請限制）。在地項目自行擬定，參考內政部建研所「騎樓及人行道路無障礙改善研究」。兩者於判準檔以來源標記區隔。

- **部署型態不變**：與地圖同為 GitHub Pages 上的靜態網站，無後端。評估結果存於 `localStorage` 並匯出為檔案。**此為刻意的取捨**：清除瀏覽資料會使未匯出的評估遺失。原規劃為研究普查（約 220 單位）而否決此作法，現範圍縮至 10–15 個示範單位，並以顯著的匯出入口與未匯出提示緩解。

- **範圍限於示範規模**：10–15 個路段，目的是證明評估層可運作並產出可接入的資料，不是完成一份研究普查。擴充至更大範圍所需的工時，由本工具記錄的實際耗時推估。

- **不在本 change 範圍**：多輪獨立評估與重測信度、重評盲化、與既有 MAPS 研究可比的分離計分。這些是研究效度需求，與本專案的用途不符（見 `docs/prior-art.md` 所述之定位）。
